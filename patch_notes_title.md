# patch_notes_title.md — Title-screen subtitle → "FrenchName ver. 0.4"

Target: Bishoujo Senshi Sailor Moon S: Jougai Rantou!? (SFC, Japan),
clean ROM SHA-1 `bc0e29ee383574443226695215496eb0d09aaa1c`.
Patched (title only) SHA-1 `e5dce7d5130909fc0e125ea621a11a10d2ded04e`.

Deliverables (built by `tools/mkpatch4.py`):
- `build/sms_title.bps` — clean → title subtitle + "FrenchName" header only (for QA).
- `build/sms_full4.bps` — clean → **all four**: 1f-link + dash-fix + palettes + title.
  (SHA-1 `51c397cb…`, 3 MB.)

## What this patch does

Replaces the red Japanese subtitle (場外乱闘!? 主役争奪戦) on the title screen with
**"FrenchName ver. 0.4"** in a clean Latin font — white glyphs with a red outline, using
the subtitle's own palette. The main Sailor Moon logo, all six menu items, and both
copyright lines are untouched. Design was validated against a true-to-resolution mockup
before implementation (the patched ROM's subtitle band is **pixel-identical** to the
approved mockup).

## Mechanism (Big-Zam-style runtime overwrite; no LZSS encoder needed)

The title graphics are LZSS-compressed and decompressed to WRAM staging, then DMA'd to
VRAM during force-blank. Rather than recompress the subtitle blob (which is byte-identical
to the Big Zam ROM — BZ doesn't touch it either), we overwrite the tiles in VRAM right
after the game loads them:

- The title CHR loader tail at **`$C3:B81F`** runs `JSL $80:8C43` (which performs the
  VRAM DMAs of all loaded title graphics, subtitle included), then `PLB; RTL`.
- We repoint that `JSL` to a **stub in an appended bank**. The stub calls the original
  `$80:8C43` (subtitle now in VRAM, still force-blank → VRAM writes safe), then DMAs our
  42 custom subtitle tiles over their VRAM slots, then `RTL`s.

Subtitle geometry: BG1, tilemap rows 13-14, 21 cells; each column is a 16px-tall glyph
split across a row-13 tile (top 8×8) and a row-14 tile (bottom 8×8). VRAM CHR base for BG1
is word `0x2000`, so tile *T* lives at VRAM word `0x2000 + T*16`. The 42 tiles form 6
contiguous VRAM runs (the gaps are copyright/other tiles, deliberately skipped):

| Run | VRAM tiles | VMADD (word) | Bytes |
|---|---|---|---|
| 1 | 0x10D–0x10F | 0x30D0 | 96 |
| 2 | 0x11D–0x11F | 0x31D0 | 96 |
| 3 | 0x120–0x12F | 0x3200 | 512 |
| 4 | 0x130–0x13F | 0x3300 | 512 |
| 5 | 0x140–0x141 | 0x3400 | 64 |
| 6 | 0x150–0x151 | 0x3500 | 64 |

## Changed bytes

- **0x3B81F–0x3B822**: `22 43 8C 80` (`JSL $80:8C43`) → `22 <lo> <hi> <bank>`
  (`JSL` to the stub; bank/addr computed from ROM size — `$E8:0000` for the standalone
  build, `$E9:0000` in the combined build).
- **Appended bank** (`$E8`/`$E9`, file 0x280000/0x290000): 195-byte DMA stub + 1344 bytes
  of custom tile data (42 tiles × 32).
- **0xFFC0** header title `…S FrenchName`, **0xFFDC/DE** checksum.

The glyphs are generated by `tools/texttiles.py` (hand-drawn 8×16 proportional pixel font,
baseline-normalized, white core / red 1px outline in the subtitle palette). Re-running it
with different text/style regenerates the tile data; `mkpatch4.py` re-lays the DMA runs
automatically.

## Verification (Mesen2, native-resolution screenshots + VRAM/CGRAM dumps)

- **Pixel-exact**: patched-ROM title subtitle band (y=100–122) is **identical** to the
  approved mockup (`ImageChops` bbox = None), on both `sms_title` and `sms_full4`.
- **Isolation**: exactly **42 VRAM tiles changed** vs clean, **all within the subtitle
  set**; every BG tilemap (VRAM 0x0000–0x3FFF) **byte-identical**; the logo CHR is
  unchanged (the only screenshot difference in the logo band is the logo's normal
  animation phase, not the patch).
- **No gameplay regression on the combined build** (`sms_full4`, savestate-driven):
  1f-link dash-out@100 / press-115-only (114 whiffs); reversal-dash meaty connects
  (P1 → hitstun 0x16); palette selection still distinct (color A vs Y CGRAM differ).
- **Header**: applied ROM reads `…S FrenchName`.
- **BPS round-trips**: `flips --apply` on a fresh clean ROM reproduces both builds
  byte-exact.

Hook safety: the stub runs once, during title-load force-blank; it calls the original
`$80:8C43` first (so the normal load is unchanged) and only adds DMAs. It executes only in
the title CHR loader — not during matches.

## Applying

```
flips --apply build/sms_title.bps  <clean ROM> <out>   # title subtitle + header only
flips --apply build/sms_full4.bps  <clean ROM> <out>   # all four patches
```
