Target: Bishoujo Senshi Sailor Moon S: Jougai Rantou!? (SFC, Japan),
clean ROM SHA-1 `bc0e29ee383574443226695215496eb0d09aaa1c`.
Patched (title only) SHA-1 `f5337f9adfaf7adcd10aaecbc3e6ea8c525e4df3`
(2026-07-30, includes the credit-line swap; `--no-credit` reproduces the previous
subtitle-only build `e5dce7d5130909fc0e125ea621a11a10d2ded04e` byte-for-byte).

Deliverables (built by `tools/mkpatch4.py`):
- `build/sms_title.bps` — clean → title subtitle + "FrenchName" header only (for QA).
- `build/sms_full4.bps` — clean → **all four**: 1f-link + dash-fix + palettes + title.
  (SHA-1 `51c397cb…`, 3 MB.)

## What this patch does

Replaces the red Japanese subtitle (場外乱闘!? 主役争奪戦) on the title screen with
**"FrenchName ver. 0.4"** in a clean Latin font — white glyphs with a red outline, using
the subtitle's own palette. The main Sailor Moon logo and all six menu items are
untouched. Design was validated against a true-to-resolution mockup before implementation
(the patched ROM's subtitle band is **pixel-identical** to the approved mockup).

**2026-07-30 addition — Big Zam credit line.** The first copyright line
(©武内直子・講談社・テレビ朝日・東映動画) is replaced with the Big Zam edition's
**"©MOONLIGHT FIGHT SOCIETY"**, rendered pixel-identically (its tiles are lifted verbatim
from BZ's title-screen VRAM). The second line **"©ANGEL 1994" is untouched** — BZ keeps
it too. Opt out with `--no-credit`.

## Mechanism (Big-Zam-style runtime overwrite; no LZSS encoder needed)

The title graphics are LZSS-compressed and decompressed to WRAM staging, then DMA'd to
VRAM during force-blank. Rather than recompress the subtitle blob (which is byte-identical
to the Big Zam ROM — BZ doesn't touch it either), we overwrite the tiles in VRAM right
after the game loads them:

- The title CHR loader tail at **`$C3:B81F`** runs `JSL $80:8C43` (which performs the
  VRAM DMAs of all loaded title graphics, subtitle included), then `PLB; RTL`.
- We repoint that `JSL` to a **stub in an appended bank**. The stub calls the original
  `$80:8C43` (subtitle now in VRAM, still force-blank → VRAM writes safe), then DMAs our
  42 custom subtitle tiles over their VRAM slots, then `RTL`s.

Subtitle geometry: BG1, tilemap rows 13-14, 21 cells; each column is a 16px-tall glyph
split across a row-13 tile (top 8×8) and a row-14 tile (bottom 8×8). VRAM CHR base for BG1
is word `0x2000`, so tile *T* lives at VRAM word `0x2000 + T*16`. The 42 tiles form 6
contiguous VRAM runs (the gaps are copyright/other tiles, deliberately skipped):

| Run | VRAM tiles | VMADD (word) | Bytes |
|---|---|---|---|
| 1 | 0x10D–0x10F | 0x30D0 | 96 |
| 2 | 0x11D–0x11F | 0x31D0 | 96 |
| 3 | 0x120–0x12F | 0x3200 | 512 |
| 4 | 0x130–0x13F | 0x3300 | 512 |
| 5 | 0x140–0x141 | 0x3400 | 64 |
| 6 | 0x150–0x151 | 0x3500 | 64 |

### Credit-line geometry (2026-07-30)

Copyright line 1 sits on BG1 tilemap rows 23–24, cols 2–29 (words `18C1…` — palette 6,
priority set); line 2 ("©ANGEL 1994") on rows 25–26. The tilemap is **byte-identical in
clean and Big Zam** — BZ swaps only the CHR contents, i.e. exactly our subtitle mechanism.
BZ changes 54 tiles; the © glyph (0x0C1 top / 0x0D1 bottom) and all of line 2 are
identical in both ROMs and are skipped. Three additional DMA runs:

| Run | VRAM tiles | VMADD (word) | Bytes |
|---|---|---|---|
| 7 | 0x0C2–0x0CF | 0x2C20 | 448 |
| 8 | 0x0D2–0x0EC | 0x2D20 | 864 |
| 9 | 0x0F0–0x0FC | 0x2F00 | 416 |

Tiles 0x0EC and 0x0FC are blank in BZ (the Latin line is shorter than the kanji line) —
blanking the tail is part of the swap. Tile data is embedded in `mkpatch4.py`
(`CREDIT_TILES_HEX`), extracted once from BZ's title-screen VRAM
(`tools/probe_title_vram.lua` → `traces/titlevram_bz_700.bin`); the BZ ROM itself stores
these tiles only in a packed/injected form (raw 4bpp / 2bpp / per-plane searches all
miss), so the VRAM lift is the faithful source. CGRAM palette 6 is identical clean vs BZ,
so colors match by construction.

## Changed bytes

- **0x3B81F–0x3B822**: `22 43 8C 80` (`JSL $80:8C43`) → `22 <lo> <hi> <bank>`
  (`JSL` to the stub; bank/addr computed from ROM size — `$E8:0000` for the standalone
  build, `$E9:0000` in the combined build).
- **Appended bank** (`$E8`/`$E9`, file 0x280000/0x290000): 276-byte DMA stub + 3072 bytes
  of custom tile data (42 subtitle + 54 credit tiles × 32). With `--no-credit`: 195-byte
  stub + 1344 bytes (the pre-2026-07-30 layout, byte-identical).
- **0xFFC0** header title `…S FrenchName`, **0xFFDC/DE** checksum.

The glyphs are generated by `tools/texttiles.py` (hand-drawn 8×16 proportional pixel font,
baseline-normalized, white core / red 1px outline in the subtitle palette). Re-running it
with different text/style regenerates the tile data; `mkpatch4.py` re-lays the DMA runs
automatically.

## Verification (Mesen2, native-resolution screenshots + VRAM/CGRAM dumps)

- **Pixel-exact**: patched-ROM title subtitle band (y=100–122) is **identical** to the
  approved mockup (`ImageChops` bbox = None), on both `sms_title` and `sms_full4`.
- **Isolation**: exactly **42 VRAM tiles changed** vs clean, **all within the subtitle
  set**; every BG tilemap (VRAM 0x0000–0x3FFF) **byte-identical**; the logo CHR is
  unchanged (the only screenshot difference in the logo band is the logo's normal
  animation phase, not the patch).
- **Credit line (2026-07-30)**: title VRAM diff vs clean = exactly **96 tiles**
  (42 subtitle + 54 credit, zero unexpected); the 54 credit tiles are **byte-identical to
  the Big Zam title VRAM dump**; tilemaps, VRAM 0x8000+, and CGRAM identical to clean;
  "©ANGEL 1994" untouched. Screenshot: `traces/titlevram_patched_700.png`. Regression
  suite on the new standalone: **ALL PASS (40)**. `--no-credit` output hashed
  byte-identical to the previous shipped build (`e5dce7d5…`).
- **No gameplay regression on the combined build** (`sms_full4`, savestate-driven):
  1f-link dash-out@100 / press-115-only (114 whiffs); reversal-dash meaty connects
  (P1 → hitstun 0x16); palette selection still distinct (color A vs Y CGRAM differ).
- **Header**: applied ROM reads `…S FrenchName`.
- **BPS round-trips**: `flips --apply` on a fresh clean ROM reproduces both builds
  byte-exact.

Hook safety: the stub runs once, during title-load force-blank; it calls the original
`$80:8C43` first (so the normal load is unchanged) and only adds DMAs. It executes only in
the title CHR loader — not during matches.

## Bumping the version (one command)

The subtitle text is a CLI flag; the font has the full glyph set for
`A–Z a–z 0–9 space .`, so a version bump needs no source edit:

```
# positionals first (src, out), then --text; then rebuild the BPS
python3 tools/mkpatch4.py "<clean ROM>" build/sms_title.sfc --text "FrenchName ver. 0.5"
tools/Flips/flips --create --bps "<clean ROM>" build/sms_title.sfc build/sms_title.bps

# combined build: apply on top of the 3-patch full build
python3 tools/mkpatch4.py build/sms_full.sfc build/sms_full4.sfc --text "FrenchName ver. 0.5"
tools/Flips/flips --create --bps "<clean ROM>" build/sms_full4.sfc build/sms_full4.bps
```

`--style` picks the treatment (`white_red` default, `red_white`, `red`). If the new text
uses a character with no glyph, the tool stops and names it (add it to `tools/texttiles.py`).
Text is capped at 21 cells and auto-centered. Running with no `--text` reproduces the shipped
v0.4 build byte-for-byte.

## Applying

```
flips --apply build/sms_title.bps  <clean ROM> <out>   # title subtitle + header only
flips --apply build/sms_full4.bps  <clean ROM> <out>   # all four patches
```
